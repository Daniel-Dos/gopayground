Payment Processor

Sistema distribuido de processamento de pagamentos em Go, baseado em microsservicos e mensageria assincrona via Kafka. Oferece pipeline completo de publicacao, consumo, validacao, persistencia e monitoramento em tempo real.

Descricao Geral

O Payment Processor e um conjunto de servicos para processamento de eventos de pagamento em tempo real. A arquitetura segue o padrao Event-Driven com Kafka como espinha dorsal, Redis para estado e idempotencia, e DynamoDB para historico permanente.

O sistema oferece tres interfaces de interacao:

  • Producer UI (/producer) — Interface web para publicar eventos manualmente
  • CLI Producer (cmd/producer) — Ferramenta de linha de comando para scripts e automacao
  • Dashboard (/) — Monitoramento em tempo real com SSE, consultas e metricas
Go 1.26 Kafka Redis DynamoDB OpenTelemetry Docker

A Producer UI se integra a este diagrama como uma pagina web servida pelo proprio servidor cmd/ui na porta 8081, publicando eventos diretamente no Kafka e no Redis Pub/Sub.

Fluxo da Producer UI

Browser (Producer UI)
    │
    │ POST /api/publish  (JSON PaymentEvent)
    ▼
Go HTTP Server (:8081)
    │
    ├── 1. Valida payload (tamanho, formato, campos)
    ├── 2. Publica no Kafka (topic: payment.events)
    │       └── Headers: source=ui-producer, timestamp
    ├── 3. Publica no Redis Pub/Sub (canal: payment:events)
    │       └── EventBus distribui para SSE clients
    └── 4. Retorna 200 + resultado (partition, offset)

Fluxo de Dados

Fluxo Completo (Producer UI ate Dashboard)

  1. Usuario preenche formulario na Producer UI em /producer
  2. Frontend valida os campos (UUID, amount > 0, currency 3 letras)
  3. Frontend envia POST /api/publish com JSON do evento
  4. Backend valida novamente (limite de 64KB, Content-Type, campos)
  5. Backend publica no Kafka via sarama.SyncProducer.SendMessage()
  6. Backend publica no EventBus (Redis Pub/Sub) para feed SSE
  7. Backend retorna {status, payment_id, partition, offset}
  8. Frontend exibe toast de sucesso e adiciona linha na tabela de historico
  9. Consumer processa o evento: valida, persiste status+historico
  10. Dashboard recebe o evento via SSE e atualiza em tempo real
Nota: A publicacao no EventBus (Redis Pub/Sub) e feita apos o Kafka, em carater best-effort. Se o Redis estiver indisponivel, o evento ainda sera publicado no Kafka e processado pelo consumer — porem, nao aparecera no feed SSE em tempo real.

API Endpoints

Todas as rotas expostas pelo servidor cmd/ui na porta 8081:

Dashboard e Arquivos Estaticos

MetodoRotaDescricao
GET / Pagina inicial (Dashboard) — servida de static/index.html
GET /producer Pagina da Producer UI — servida de static/producer.html
GET /static/* Arquivos estaticos (CSS, JS, imagens)

API de Dados (Dashboard)

MetodoRotaDescricao
GET /api/events Stream SSE de eventos em tempo real. Heartbeat a cada 30s. Conexao limitada a 100 simultaneas.
GET /api/payments Lista pagamentos do Redis. Filtros opcionais: ?payment_id= (LIKE), ?status= (exato). Timeout: 5s.
GET /api/payments/{id}/history Historico completo de um pagamento no DynamoDB. Ordenado por timestamp ascendente. Timeout: 10s.
GET /api/metrics Metricas agregadas: total_processed, by_status, success_rate, dlq_count. Timeout: 5s.
GET /healthz Health check: ping no Redis. Retorna 200 se ok, 503 se Redis down.

API de Publicacao (Producer UI)

MetodoRotaDescricao
POST /api/publish Publica um evento de pagamento no Kafka e no EventBus. Payload maximo: 64KB. Timeout: 10s.
Content-Type: application/json
Retorno: {status, payment_id, partition, offset}
POST /api/publish/bulk Gera e publica N eventos aleatorios (1 a 100, default 10). Payload: {"count": N}. Timeout total: 30s.
Retorno: Array de resultados com partition/offset ou erro por item.

POST /api/publish — Exemplo

CopiarPOST /api/publish
Content-Type: application/json

  "status": "confirmed",
  "amount": 150.00,
  "currency": "BRL",
  "description": "Pedido #12345"
}

Resposta 200:
{
  "status": "published",
  "payment_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "partition": 0,
  "offset": 42

{ "count": 3 }

Resposta 200:

  {"payment_id": "uuid-2", "status": "failed", "partition": 1, "offset": 12},

Producer UI

A Producer UI e uma interface web para publicar eventos de pagamento no Kafka diretamente do navegador. Acessivel em http://localhost:8081/producer.

Dica: Para um guia detalhado de uso da Producer UI, veja o Guia da Producer UI.

Tecnologias

  • HTML5 — Estrutura semantica
  • CSS3 — Dark theme, responsivo, reutiliza style.css da dashboard
  • JavaScript Vanilla — Zero frameworks, zero dependencias
  • Embed.FS — Assets embutidos no binario Go

Funcionalidades

FuncionalidadeDescricao
Formulario de publicacaoCampos: Payment ID (UUID, auto-gerado), Status (select), Amount, Currency, Description
Preview JSON ao vivoPre-visualizacao do payload JSON atualizada em tempo real conforme o usuario digita
Publicacao unicaEnvia POST /api/publish com validacao frontend antes do envio
Publicacao em loteGera e publica 10 eventos aleatorios com um clique
Historico de sessaoTabela com ate 50 ultimas publicacoes, persistida em sessionStorage
Toasts de feedbackNotificacoes visuais de sucesso (verde), erro (vermelho) e aviso (amarelo)
Detalhes do KafkaParticao e offset retornados apos cada publicacao bem-sucedida

Formatos de Evento

PaymentEvent (Kafka)

Copiar{
  "payment_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",  // UUID v4, obrigatorio
  "status": "confirmed",                                    // pending|confirmed|failed|refunded
  "amount": 150.00,                                         // float64, > 0
  "currency": "BRL",                                        // ISO 4217, 3 letras
  "description": "Pedido #12345",                           // opcional, max 255 chars
  "timestamp": "2026-05-25T12:00:00Z"                      // RFC 3339, auto-preenchido
}

PaymentStatus (Redis)

Redis Hash "payment:<payment_id>"
  HSET payment:<payment_id> payment_id "uuid" status "confirmed" updated_at "2026-05-25T12:00:00Z"
  TTL: 168 horas (7 dias)

PaymentHistory (DynamoDB)

Table: payment_history
  PK: payment_id  (String, Hash Key)
  SK: timestamp   (String, Range Key)
  Attributes: status, amount, currency, description, processed_at, trace_id
  Billing: PAY_PER_REQUEST

SSE Event Stream

event: payment
data: {"payment_id":"...","status":"confirmed","amount":100,"currency":"BRL","timestamp":"..."}

event: heartbeat
data: {}

Quick Start

Subir infraestrutura

Copiar# Subir todos os servicos
docker-compose up -d

# Ou apenas a infraestrutura minima
docker-compose up -d kafka redis floci otel-collector

Executar UI (com Producer)

Copiar# A UI inclui suporte a Kafka para publicacao
go run ./cmd/ui

# Acessar:
#   Dashboard: http://localhost:8081/
#   Producer:  http://localhost:8081/producer

Executar Consumer

Copiargo run ./cmd/consumer

Publicar evento via CLI

Copiargo run ./cmd/producer publish \
  --status confirmed \
  --amount 150.00 \
  --currency BRL \
  --description "Pedido #12345"
