Guia da Producer UI

Como publicar eventos de pagamento no Kafka diretamente do navegador.

Introducao

A Producer UI e uma interface web que permite publicar eventos de pagamento no Kafka sem precisar abrir o terminal. Ela e servida pelo proprio servidor da UI (cmd/ui) na porta 8081.

Acesso: http://localhost:8081/producer

A pagina oferece:

  • Formulario completo com todos os campos do evento de pagamento
  • Preview JSON ao vivo enquanto voce digita
  • Publicacao de evento unico ou 10 eventos aleatorios
  • Tabela de historico com as ultimas 50 publicacoes da sessao
  • Notificacoes visuais (toasts) de sucesso e erro

Preview JSON ao Vivo

Ao lado (ou abaixo, em mobile) do formulario, ha um bloco de pre-visualizacao JSON que se atualiza em tempo real conforme voce preenche os campos. Isso permite ver exatamente como os dados serao enviados antes de clicar em "Publicar".

O preview destaca:

  • Valores em azul para strings
  • Valores em amarelo para numeros
  • O texto <auto-gerado> quando o campo Payment ID esta vazio

Como Publicar um Evento Unico

  1. Preencha os campos do formulario (ou deixe Payment ID em branco para auto-gerar)
  2. Confira o preview JSON ao lado para garantir que os dados estao corretos
  3. Clique no botao "Publicar" (ou pressione Ctrl+Enter)

Apos o envio:

  • Sucesso: Um toast verde aparece com os primeiros caracteres do Payment ID. Uma nova linha e adicionada na tabela de "Ultimas Publicacoes" com a particao e o offset retornados pelo Kafka.
  • Erro: Um toast vermelho exibe a mensagem de erro. O formulario mantem os dados preenchidos para que voce possa corrigir e tentar novamente.
Dica: Use o atalho Ctrl+Enter para publicar mais rapidamente sem precisar clicar no botao.

Como Publicar 10 Eventos Aleatorios

Para testar o sistema com multiplos eventos de uma vez, clique no botao "Publicar 10 Aleatorios".

O que acontece:

  1. O frontend envia uma requisicao POST /api/publish/bulk com {"count": 10}
  2. O backend gera 10 eventos aleatorios usando producer.GenerateBulkEvents(10)
  3. Cada evento e publicado no Kafka individualmente
  4. O resultado e um array com partition e offset para cada evento
  5. Os eventos bem-sucedidos sao adicionados a tabela de historico

O toast de resultado mostra um resumo, por exemplo: "9 evento(s) publicado(s) com sucesso. 1 falha(s)."

Nota: O botao fica desabilitado durante o processamento. Eventos com falha sao exibidos com erro na tabela de historico.

Entendendo os Resultados

Apos uma publicacao bem-sucedida, o servidor retorna tres informacoes importantes:

CampoDescricao
payment_idUUID do pagamento que foi publicado
partitionNumero da particao do Kafka onde o evento foi armazenado
offsetPosicao do evento dentro da particao (incrementado a cada nova mensagem)

Esses dados aparecem na tabela de "Ultimas Publicacoes" e permitem rastrear o evento no Kafka.

Historico de Sessao

A tabela de "Ultimas Publicacoes" mantem um registro de todos os eventos que voce publicou durante a sessao atual. As colunas sao:

  • ID — Payment ID do evento (truncado se muito longo)
  • Situacao — Status do evento (Confirmado, Falhou, etc.) com badge colorido
  • Valor — Valor em Reais ou outra moeda
  • Particao — Particao do Kafka onde foi publicado
  • Offset — Offset dentro da particao
  • Data/Hora — Timestamp da publicacao formatado em pt-BR

Caracteristicas do historico:

  • Armazenado em sessionStorage do navegador (persiste durante a sessao, mas e perdido ao fechar a aba)
  • Limite de 50 eventos (os mais antigos sao descartados automaticamente)
  • Ordenado do mais recente para o mais antigo
  • Botao "Limpar Historico" para remover todos os registros

Cenarios de Erro

CenarioO que apareceO que fazer
Kafka indisponivel Toast vermelho: "Falha ao publicar: kafka not available" Verifique se o Kafka esta rodando. A UI funciona mesmo sem Kafka — apenas a publicacao e afetada.
Valor invalido (<= 0) Validacao frontend impede o envio. Toast vermelho: "Valor deve ser maior que zero." Digite um valor valido (ex: 100.00).
Moeda invalida Validacao frontend: "Moeda deve ter exatamente 3 letras (ex: BRL, USD, EUR)." Digite um codigo ISO 4217 valido com exatamente 3 caracteres.
UUID invalido Validacao frontend: "ID do pagamento invalido. Deve ser um UUID valido." Corrija o UUID ou deixe o campo vazio para auto-gerar.
Descricao muito longa Validacao frontend: "Descricao muito longa (maximo 255 caracteres)." Reduza a descricao para no maximo 255 caracteres.
Erro no servidor Toast vermelho com o codigo do erro HTTP Verifique os logs do servidor para mais detalhes.
Importante: Em caso de erro, o formulario nao e limpo — seus dados permanecem para que voce possa corrigir e tentar novamente.

Navegacao entre Paginas

O header da pagina possui dois links de navegacao:

  • Dashboard (/) — Leva para a pagina de monitoramento com feed SSE, lista de pagamentos e metricas
  • Producer (/producer) — Volta para a pagina de publicacao (destacado quando ativo)

Isso permite que voce publique um evento e rapidamente va para a Dashboard para ve-lo sendo processado em tempo real.

Dicas e Boas Praticas

  • Use o preview JSON para validar os dados antes de publicar — isso evita erros de formatacao
  • Deixe o Payment ID vazio se nao precisar de um ID especifico — o servidor gera um UUID automaticamente
  • Use "Publicar 10 Aleatorios" para gerar dados de teste rapidamente e ver o fluxo completo funcionando
  • Combine com a Dashboard — publique um evento e va para a Dashboard para ve-lo sendo processado em tempo real via SSE
  • O historico e por sessao — fechar a aba perde os registros. Use o CLI Producer se precisar de persistencia.
